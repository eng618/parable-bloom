# 📖 Reference Documentation

Reference documentation is **information-oriented**. It provides technical descriptions, specifications, schemas, design token catalogs, and compliance requirements for Parable Bloom.

It serves as the definitive source of truth when you need exact facts, limits, configurations, or syntax.

---

## Available Reference Documents

### 1. [Level System Specification](level-system.md)

Comprehensive technical specification for level data:

- JSON file schema and coordinate system.
- Grid boundaries and 100% occupancy definitions.
- Structural validation rules (4-connectivity, neck-head orientation, cycle prevention).
- Difficulty tier configurations (Seedling, Nurturing, Flourishing, Transcendent).

### 2. [Color System & Token Usage](color-usage.md)

Design token specifications and palettes:

- Semantic color palette (Light and Dark mode).
- Garden-themed vine colors and bloom state animations.
- Hexadecimal code references and WCAG contrast compliance.

### 3. [Scripture Licensing & Compliance](scripture-licensing.md)

Legal parameters and technical safeguards for Bible translations:

- Permitted translations and public domain vs. copyrighted terms (KJV, WEB, NET, ESV, CSB).
- Mandatory copyright notices and attribution statements.
- Technical limits (verse counts, proportion caps).

### 4. [Third-Party Attributions](attributions.md)

Credits, licenses, and notices for third-party libraries, audio tracks, and graphical assets used throughout the project.

### 5. [Launch Readiness Audit](launch-readiness-audit.md)

Pre-launch audit criteria and technical readiness checklist across code, UX, security, and release assets.

### 6. [Bug & Issue Tracker](known-issues.md)

Actionable, running checklist of known bugs, technical debt, and issues organized by severity with checkable progress marks.
